Market

Trader.dev tests Bybit USDT perpetuals: BTCUSDT, ETHUSDT, SOLUSDT and the rest of its coverage. Leave the dates empty for the longest window it has.

Strategy

Execution

Trader.dev runs every backtest at 100% of equity per trade, 0.05% commission a side, and fills on the signal bar's close. Those are fixed, so the app has no controls for them.

Stops and targets

1R is the distance from entry to the stop. A strategy's own stop and target come first; then the ATR stop beats stop loss %, and reward:risk beats take profit %. Reward:risk and break-even need a stop.

Entry filter

Longs only above this SMA, shorts only below it. It blocks new entries; exits always go through.

      Strategy API
      
          
      
            
      A strategy is one JavaScript file in strategies/ that describes its parameters and returns the Pine Script Trader.dev runs:
      

      export default {
  name, description,
  params: { len: 20 },
  pine({ p }) {
    return {
      body: `ma = ta.sma(close, ${p.len})`,
      longEntry: 'ta.crossover(close, ma)',
      shortEntry: 'ta.crossunder(close, ma)',
    };
  },
};
      
            
      params
      
            
      len: 20 or { value, min, max, step, label }. Booleans become checkboxes, { value: 'EMA', options: [...] } a dropdown here and a plain string input in the Pine, because the engine's parser rejects an options list. Every parameter becomes a Pine input, which is what lets the Optimize tab sweep it.
      
            
      pine({ p, params })
      
            
      p.len is the name of that parameter's Pine input (p_len), so put it straight into the code. params.len is its current value, for when you need the number itself at generation time.
      
            
      Return an object:
      
            
        
              
      • body — Pine that computes your indicators and any helper variables.
        • 
              
      • longEntry, shortEntry — Pine expressions that are true when a trade opens. At least one is required.
        • 
              
      • longExit, shortExit — true when the position closes on a signal.
        • 
              
      • longStop, shortStop, longTarget, shortTarget — price levels read at entry. They win over the sidebar's stop and target; return na to fall back to it.
        • 
              
      • plots — [{ title, expr }], drawn on the Trader.dev report.
        • 
            
      
            
      What the app adds
      
            
      The strategy() header, the inputs, the entry and exit orders, and whichever stops, targets and filters are switched on in the sidebar. The Pine sent tab shows the finished script.
      
            
      Pine the engine allows
      
            
      ta.sma ema rma wma vwma hma swma alma linreg median mode percentile_nearest_rank percentile_linear_interpolation percentrank rsi stoch cci cmo mfi roc mom change tsi wpr cog macd bb bbw kc kcw dmi supertrend sar crossover crossunder cross barssince valuewhen rising falling pivothigh pivotlow highest lowest highestbars lowestbars range stdev dev variance correlation cum max min atr tr vwap obv pvt accdist iii wad wvad nvi pvi
      
            
      Also open high low close volume time bar_index hl2 hlc3 ohlc4, na() nz() fixnan(), math.*, var, :=, if/for, and history access with [].
      
            
      Not available: request.security, arrays and maps, user-defined functions, strategy.cancel, strategy.order and pyramiding above 1.
      
            
      Sessions
      
            
      Trader.dev's markets trade around the clock, so there is no trading session to anchor to. For a daily anchor, work it out from time: newDay = math.floor(time / 86400000) != math.floor(time[1] / 86400000). The two VWAP strategies do this.
